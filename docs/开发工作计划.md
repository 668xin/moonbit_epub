# Moon EPUB 开发工作计划

## 一、总体目标

在 MoonBit 生态中实现一个完整的 EPUB 3 电子书生成引擎，从结构化内容输入产出符合 W3C EPUB 3.3 规范、
可被主流阅读器直接打开的 `.epub` 文件，并配套结构校验器与 CLI。

- 目标代码量：**7,000 – 9,500 行**（含测试），落在赛事要求的 4K–10K 区间内
- 阶段划分：9 个阶段（S0–S8）
- Git 提交节奏：每阶段 1–2 次提交，**总计 17 次**
- 许可证：Apache-2.0（OSI 认可）
- 发布目标：mooncakes.io 可安装，CI 覆盖 check / build / test 全流程

## 二、技术前提（已验证）

以下事项已在开工前实测确认，不是假设：

**1. 编译链路已打通。** 本机 moon 工具链的 `core` 注入依赖 `MOON_CORE_OVERRIDE` 环境变量指向
核心库源码目录。已实测 `moon check` / `moon test` / `moon build` 三流程全部通过，
并已用 5 个真实 EPUB 场景探针（XML 转义、UUID 派生、字节缓冲、CRC32、UTF-8 长度）
验证核心库 API 可用。CRC32 实现已与 zlib 做对照校验，四种输入全部一致。

**2. 目标后端必须是 js，不能用默认的 wasm-gc。** 这是实测发现的关键约束：

| 后端 | check | build | test | run 输出 | 可用性 |
|---|---|---|---|---|---|
| `wasm-gc` | ✓ | ✓ | ✗ 崩溃 `0xc0000139` | ✗ **静默丢失** | **不可用** |
| `js` | ✓ | ✓ | ✓ 13/13 通过 | ✓ 正常 | **采用** |
| `native` | — | ✗ 无 C 编译器 | — | — | 环境缺失 |

`wasm-gc` 下 `println` 无任何输出（CLI 工具直接废掉），测试运行器抛
`exit code 0xc0000139`。因此 `moon.mod` 中设 `preferred_target = "js"`，
CI 与所有命令统一追加 `--target js`。

**3. 方向经全量生态核查确认为空白。** 对 mooncakes.io 全量 2,879 个模块 / 845 个作者做检索：

| 检索词 | 命中数 | 实际情况 |
|---|---|---|
| `epub` | 3 | 2 个是读取方向（`doc_parser`、`markitdown`），1 个为子串误匹配 |
| `opf` | 0 | — |
| `ncx` | 0 | — |
| `xhtml` | 0 | — |
| `mobi` / `azw` / `fb2` | 0 / 0 / 0 | — |

两个名字里带 "book" 的包（`spectacleCase/moonbook`、`himeno/mopress`）均为静态站点生成器，
不产出 EPUB。**结论：EPUB 的"生成"能力在生态中完全缺失。**

**4. 关键依赖已就位。** ZIP 侧有 `fzip`（fflate 移植）、`bobzhang/zipc`；
XML 侧有 `marianoguerra/xml`（流式读写器）。但本项目打包层与 XML 序列化层
计划自行实现（见下方风险说明），依赖仅作对照与兜底。

**5. 多包分层结构已验证。** 已实测 MoonBit 的 `src/<pkg>/moon.pkg` 分层与跨包
`@alias` 引用可正常工作，编译通过。

## 二·五、目录结构

```
moon_epub/
├── moon.mod                    模块元信息（preferred_target = "js"）
├── env.sh / env.ps1            MOON_CORE_OVERRIDE 固化脚本
├── .github/workflows/ci.yml    CI：check / build / test / fmt
├── docs/                       申报书与开发计划
├── examples/                   可运行示例（S8）
└── src/
    ├── moon.pkg                顶层门面包：聚合全部子包公开 API
    ├── entry.mbt
    ├── spec/                   S0  规范常量 + 基础工具（最底层，零依赖）
    ├── model/                  S1  书籍领域模型
    ├── xhtml/                  S2  XHTML5 内容文档生成
    ├── opf/                    S3  OPF 包文档序列化
    ├── nav/                    S3  nav.xhtml 与 toc.ncx
    ├── zip/                    S4  ZIP 写入器 + CRC32
    ├── ocf/                    S4  OCF 容器布局与打包
    ├── assets/                 S5  CSS 样式与资源管理
    ├── cfi/                    S5  EPUB CFI 定位路径
    ├── a11y/                   S6  可访问性元数据
    ├── media/                  S6  Media Overlays (SMIL)
    ├── validate/               S7  结构校验器
    └── cli/                    S8  命令行入口（is-main）
```

依赖方向单向向下，无环：`cli → validate → ocf → zip`，
`cli → ocf → model`，`opf/nav/xhtml → spec`，`spec` 不依赖任何包。

## 三、阶段与提交计划

### S0：工程骨架与规范分词（1 次提交）

- `moon.mod` 元信息、目录结构、CI 工作流、LICENSE
- 规范常量层：EPUB 命名空间 URI、Media Type 表、OCF 保留名、Dublin Core 元素名
- 基础工具：XML 转义、ID 规范化、UTF-8 长度、路径拼接与规范化

> 提交 1：`feat(core): 工程骨架、EPUB 规范常量与基础工具层`

### S1：书籍领域模型（2 次提交）

- `Book` / `Chapter` / `Resource` / `Metadata` / `ManifestItem` / `Spine` 类型定义
- 章节树构建与遍历、阅读顺序（Spine）维护、清单（Manifest）管理与 ID 唯一性约束
- 元数据模型：Dublin Core 全集 + `meta` 属性 + series/collection

> 提交 2：`feat(model): 书籍领域模型与章节树`
> 提交 3：`feat(model): 元数据、清单与阅读顺序模型`

### S2：XHTML 内容文档生成（2 次提交）

- XHTML5 文档骨架与 head/body 结构生成
- 章节内容渲染：标题层级、段落、列表、引用、代码块、表格、图片
- 脚注与注记（`epub:type` 语义属性）支持

> 提交 4：`feat(xhtml): XHTML5 内容文档骨架与块级元素渲染`
> 提交 5：`feat(xhtml): 内联元素、脚注与 epub:type 语义`

### S3：OPF 包文档与导航文档（2 次提交）

- OPF `package` 文档完整序列化（metadata / manifest / spine / guide）
- `nav.xhtml`（EPUB 3 标准导航）生成，含嵌套目录树
- `toc.ncx`（EPUB 2 向后兼容）生成

> 提交 6：`feat(opf): OPF 包文档序列化`
> 提交 7：`feat(nav): nav.xhtml 与 toc.ncx 双轨导航生成`

### S4：ZIP / OCF 容器打包（2 次提交）

- ZIP 写入器：本地文件头、中央目录、数据描述符、CRC32 校验
- OCF 布局约束：`mimetype` 首条目且 STORED 不压缩、`META-INF/container.xml` 生成
- 字节缓冲流式输出，避免整包驻留内存

> 提交 8：`feat(zip): ZIP 写入器与 CRC32 校验`
> 提交 9：`feat(ocf): OCF 容器布局与端到端打包`

### S5：样式、资源与 CFI（2 次提交）

- 内置阅读器友好 CSS、自定义 CSS 注入、字体与图片资源登记
- EPUB CFI：内容定位路径的构造与解析
- 资源去重与 MIME 类型推断

> 提交 10：`feat(assets): CSS 样式表与资源登记管理`
> 提交 11：`feat(cfi): EPUB CFI 定位路径构造与解析`

### S6：可访问性与媒体覆盖（2 次提交）

- 可访问性元数据：`schema:accessMode` / `accessibilityFeature` / `accessibilitySummary`
- Media Overlays：SMIL 文档生成，文本-音频对时描述
- 有声书章节模型扩展

> 提交 12：`feat(a11y): 可访问性元数据体系`
> 提交 13：`feat(media): Media Overlays SMIL 文档生成`

### S7：结构校验器（2 次提交）

- 规范级检查规则：必需文件存在性、mimetype 位置与压缩方式、清单一致性、
  spine 引用完整性、ID 唯一性、元数据必需项、资源可达性
- 诊断报告：定位到文件与字段，分级（error / warning / info）
- 机器可读输出模式

> 提交 14：`feat(validator): EPUB 结构校验规则集`
> 提交 15：`feat(validator): 诊断报告与机器可读输出`

### S8：CLI、示例与发布（2 次提交）

- CLI 子命令：`build` / `check` / `inspect`
- 示例工程：最小书籍、多章节书籍、自定义样式书籍
- README、API 文档、测试补全、mooncakes.io 发布

> 提交 16：`feat(cli): build/check/inspect 子命令与示例工程`
> 提交 17：`docs: README、API 文档与 mooncakes.io 发布`

## 五、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 核心库无文件 IO | 无法直接写盘 | 保持零依赖：字节流进出，CLI 侧由 shell 重定向落盘（与 `modbus_lint` 同一策略） |
| `wasm-gc` 后端不可用 | 输出丢失、测试崩溃 | `moon.mod` 设 `preferred_target = "js"`，所有命令与 CI 统一带 `--target js` |
| 环境变量依赖易遗忘 | 编译失败被误判为代码问题 | 仓库根放 `env.sh` / `env.ps1` 固化 `MOON_CORE_OVERRIDE`，README 显著说明 |
| ZIP 细节繁多（中央目录偏移、数据描述符） | 生成的包阅读器打不开 | S4 阶段先用 Python `zipfile` 做产物对照验证，再固化测试用例 |
| EPUB 规范体量大 | 范围蔓延 | 已在申报书明确排除阅读/渲染/DRM/固定版式 |
| 无官方 EPUBCheck 对照 | 规范符合性无外部背书 | 自建校验器覆盖核心规则，并对生成产物做阅读器实测 |
